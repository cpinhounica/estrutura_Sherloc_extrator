Parâmetros Sherlock — o que a seguradora precisa enviar

Dois momentos distintos: configuração de onboarding (uma vez) e payload por sinistro (cada chamada)

Parte 1 — Configuração de onboarding (enviada uma vez, salva no tenant)
⚙ Enviado uma vez no cadastro
Esses parâmetros são enviados pela seguradora durante o onboarding e ficam salvos em dbProteoKnowledge.tenants. A partir daí, toda chamada de sinistro os herda automaticamente — a seguradora não precisa repetir nada.

1.1 — Identificação do tenant

CampoTipoObrig.Descrição / Exemplo
tenant_id string Sim
Identificador único da seguradora no sistema
ex: "seg-porto-001"
nome string Sim
Nome da seguradora
ex: "Porto Seguro S.A."
cnpj string Sim
CNPJ da seguradora
ex: "61.198.164/0001-60"
api_key string Sim
Chave de autenticação gerada pelo sistema Proteo no cadastro
ramos_contratados array[string] Sim
Ramos habilitados para essa seguradora
ex: ["auto", "vida", "residencial"]
contato_tecnico object Sim
Email e nome do responsável técnico para notificações
ex: { "nome": "João Silva", "email": "joao@seguradora.com.br" }

1.2 — Adapter de campos (mapa de-para)

Só precisa enviar o que for diferente do canônico. Se a seguradora já usa os mesmos nomes de campo que o modelo canônico do Sherlock, essa seção fica vazia e não precisa ser enviada.
CampoTipoObrig.Descrição / Exemplo
adapter.formato_entrada string Não
Formato dos dados enviados pela seguradora
ex: "json" | "xml" | "csv" — padrão: "json"
adapter.mapa_campos object Não
Mapa de campo deles → campo canônico. Só os que diferem.
ex: { "end_segurado": "insured.address", "dt_sinistro": "claim.occurredAt" }

1.3 — Regras ativas por ramo

As regras do catálogo ficam todas ativas por padrão para cada ramo contratado. A seguradora só informa o que quer desligar ou adicionar como extra.
CampoTipoObrig.Descrição / Exemplo
regras.desativar array[string] Não
IDs de regras do catálogo que não se aplicam a essa seguradora
ex: ["regra-esporte-radical", "regra-bo-endereco"]
regras.extras array[object] Não
Regras específicas dessa seguradora que não existem no catálogo
ex: [{ "nome": "Limite regional SP", "primitiva": "comparar", "campo": "claim.location.uf", "operador": "igual", "valor": "SP" }]
regras.tolerancias object Não
Parâmetros numéricos das regras que têm threshold ajustável
ex: { "distancia_endereco_bo_km": 5, "janela_atraso_aviso_dias": 30 }

1.4 — Condições gerais (upload por produto)

CampoTipoObrig.Descrição / Exemplo
condicoes_gerais[].ramo string Sim
Ramo ao qual esse documento de condições pertence
ex: "auto"
condicoes_gerais[].produto_id string Sim
Identificador do produto/apólice dentro do ramo
ex: "auto-premium-v2"
condicoes_gerais[].arquivo file (PDF) Sim
PDF das condições gerais. O Sherlock indexa para RAG automaticamente.
condicoes_gerais[].vigencia object Sim
Período de validade dessas condições
ex: { "inicio": "2024-01-01", "fim": "2024-12-31" }
Parte 2 — Payload por sinistro (enviado a cada chamada à API)
📨 Enviado a cada sinistro
Envelope fixo + ramo_payload variável por ramo. O envelope é sempre igual — a seguradora integra uma vez. Só o ramo_payload muda dependendo do ramo do sinistro.

2.2 — ramo_payload por ramo

Apenas o bloco ramo_payload muda. O resto do envelope é sempre igual.

🚗 Auto ramo: "auto"
veiculo.placa
veiculo.chassi
veiculo.modelo
veiculo.ano
veiculo.km_atual
condutor.nome
condutor.cnh
condutor.categoria_cnh
condutor.validade_cnh
bo_numero ← cruzamento endereço
terceiros [ ] ← nome, cpf, placa
tipo_sinistro: colisao|roubo|incendio
❤️ Vida / Saúde ramo: "vida"
segurado.data_nascimento
segurado.profissao
beneficiario.nome
beneficiario.cpf
beneficiario.parentesco
cid10 ← para exclusão por doença prévia
data_obito ← se aplicável
causa_morte
carencia_cumprida: true|false
atividade_risco: true|false ← exclusão
✈️ Viagem ramo: "viagem"
viagem.destino
viagem.data_embarque
viagem.data_retorno
viagem.companhia_aerea
viagem.numero_voo
tipo_sinistro: bagagem|cancelamento|medico
comprovante_extravio_ref ← extrator_ref
valor_bagagem_declarado
esporte_radical: true|false ← exclusão
🏠 Residencial ramo: "residencial"
imovel.tipo: casa|apartamento
imovel.endereco_completo
imovel.area_m2
imovel.ocupacao: proprio|alugado
tipo_sinistro: incendio|roubo|alagamento
bo_numero ← para roubo/furto
laudo_pericia_ref ← extrator_ref
imovel_habitado_na_ocorrencia: true|false
